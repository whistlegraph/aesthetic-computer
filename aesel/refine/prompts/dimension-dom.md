# YOUR DIMENSION: WHAT A PIECE-MAKER KNOWS

You own the craft the model lacks: what this kind of piece needs to feel
finished, the AC API facts it got wrong, the layout, motion, sound and input
conventions a practised author would not forget. Turn it into rules the model
can apply and check:

- AN API FACT: the exact call, argument order or name it reached for wrongly.
  Only what the record or the shipped guides establish — never invent API.
- A CRAFT RULE: the trigger, what to do, and how to see that it was done
  ("a piece with motion derives it from time, so it runs the same at any
  frame rate").
- AN OMISSION: what a person asking for this would expect without saying it —
  that a game is playable by touch as well as keys, that sound waits for a tap.

Do not diagnose tool use, retries or verification. A parallel candidate owns
procedure; stay on what a piece-maker knows.
